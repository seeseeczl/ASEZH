## Context

见 proposal.md。节点标题的显示链路是：`ASENativeDisplay.Title` 先用节点类型全名核对白名单 `ASENativeTypes.Names`，通过后再拿节点默认名查 `node_title` 词典。两层任何一层缺失都会静默回退英文，而且 Search 列表与画布标题共用这条链路，所以一处缺失会同时表现为"节点名没汉化"。

## Goals / Non-Goals

目标：让"内置节点标题是否覆盖"变成可机器核对的事实，并补齐当前 ASE 1.9.9.5 的全部缺口。
非目标：不把白名单放宽成"任何类型都翻译"——自定义子类与 Flyme 分类必须继续排除。

## Decisions

- 白名单继续用类型全名精确匹配，只补内置类型；不使用基类或命名空间前缀匹配，避免把自定义节点卷入翻译。
- `Toggle Switch` 走与 `ScreenColorNode` / `StaticSwitch` 相同的"标题绘制点"补丁模式，保持一处一锚点、可回滚。
- 审计命令按同一个白名单文件与同一份词典核对，避免审计规则与运行时规则分叉。

## Risks / Trade-offs

- 白名单扩大意味着这些类型在画布上也会参与标题翻译 → 只在"当前文本等于节点默认名"时翻译，重命名节点不受影响。
- 新增标题锚点同样是版本敏感的 → 与既有做法一致，锚点先在本地 ASE 上逐条校验，再由发布门禁跑完整生命周期。

## Migration Plan

0.0.15 只新增白名单项、词条与一条标题钩子；已接入的工程重新扫描时该项报 `ready`，再应用一次即可补齐。
