# 对抗性审计报告 — ASEZH 0.0.16 FAGUI 属性名排除

## 审计边界

- 审计对象：0.0.15（`4c1d646`）之后的全部改动：`ASEUiCaptionPatchCatalog` 新增一条"保持原文"补丁、`PropertyNode.cs` 合成 fixture 片段、0.0.16 的版本与文档产物。
- 需求来源：用户要求把 FAGUI 属性名从汉化范围里排除（并确认截图中的中文并非 ASEZH 产物）。
- 方法：核对运行时翻译链路与实际调用点；在许可 ASE 1.9.9.5 与合成 fixture 上验证锚点；跑合成 + 许可 ASE 全生命周期、EditMode、静态与 OpenSpec 校验。
- 非目标：不修改 ASE 源码里 FAGUI 属性名文本本身；不覆盖 Windows / 其他 Unity 版本。
- 未覆盖范围：未在 1.9.8.x 上验证新锚点（见 AA-RISK-001）。

## 威胁与失败模型

- 资产：FAGUI 属性名的显示正确性、普通属性列表与其它界面文案的既有汉化、消费者的 ASE 源码。
- 最贵失败：为了排除一处文案而误伤其它使用同一英文词的位置；或新锚点让整次接入失败。
- 本次改动的信任边界不变：仍然只改显示参数，未命中的差异一律 fail-closed。

## Findings

### AA-CORR-004 — 排除方式若走"删词"会误伤其它界面（P2，设计选择，已按安全方案实施）

- 位置：`Editor/Installer/ASEUiCaptionPatchCatalog.cs` → `ui-optout-fagui-attribs`
- 触发条件：若采用"从词典删掉 `Foldout` / `Ramp` / `Vector` / `HelpBox` / `Tooltip` / `KeywordDesc`"来实现排除。
- 错误行为：这些英文词并非 FAGUI 专用；删除词条会让其它走 `ASELocale.T` 的界面位置一并失去翻译，且已发布工程的显示会回退。
- 影响：一个局部排除需求会变成全局回退，且难以察觉。
- 证据等级：已验证（词典中这些键在 `DisplayLookupOrder` 的通用表内，任何 `T()` 调用点都会命中）。
- 状态：已按安全方案实施——不改词典，改为在 FAGUI 调用点直接使用 Unity 原生 `EditorGUILayout.ToggleLeft`，把该列表整条绕开显示层。

### AA-SCOPE-001 — 排除范围只覆盖 FAGUI 属性勾选列表（P3，已披露）

- 位置：`PropertyNode.cs` 的 `m_selectedFaguiAttribsArr` 循环
- 触发条件：FAGUI 面板里其它字段（`Keys` / `Property` / `Compare` / `Value` / `Logic`）仍走被包装的绘制方法。
- 错误行为：这些字段仍会被汉化；若用户的"排除 FAGUI"包含它们，则范围偏小。
- 影响：仅影响显示一致性，不影响数据；用户可明确后扩大范围。
- 证据等级：已验证（同一面板内这些调用点仍使用 `EditorGUILayoutTextField` / `EditorGUILayoutEnumPopup` 等被包装方法）。
- 状态：未修复，按用户当前描述只排除属性名；如需扩大范围按同一"保持原文"模式追加。

### AA-RISK-001 — 新增锚点继续扩大"整次预检被拒"的暴露面（P2，未修复，沿用）

- 位置：本批次新增 1 条锚点（累计 45 条）。
- 触发条件：消费者使用 1.9.8.x、裁剪版或改动过该行的 ASE 源码。
- 错误行为：锚点不匹配 → 整次 Apply 被拒。
- 影响：与 0.0.15 审计记录同源，仍是"扩覆盖 vs 保兼容"的结构性取舍。
- 证据等级：高置信推断（代码级推理；1.9.8.x 未运行）。
- 状态：未修复，`AA-OPT-007`。

## 已检查未发现可行动缺陷的区域

- 语义等价：`EditorGUILayoutToggleLeft( string, bool, params )` 与 Unity 原生 `EditorGUILayout.ToggleLeft( string, bool, params )` 签名一致；ASE 包装只是"先 `ASELocale.T` 再调原生"，替换后勾选行为与返回值不变，唯一差别是不翻译。
- 锚点精确性：许可 ASE 1.9.9.5 与合成 fixture 均命中 1 次该 Find；替换后 Marker 存在、Find 消失，`VerifyApplied` 为 `applied`，说明幂等且不重复打。
- 影响面隔离：Find 只匹配 `m_selectedFaguiAttribsArr`（FAGUI 列表），普通属性列表 `m_selectedAttribsArr` 的调用点不受影响；集成门禁的 `VerifyApplied` 覆盖了这一点。
- 词典未被改动：0.0.16 不含词典增删，`Foldout` / `Ramp` / `Vector` 等词的既有翻译在其它位置继续生效。
- 交付一致性：package.json / README / CHANGELOG 三处版本为 0.0.16，CHANGELOG 连续 `0.0.16 → 0.0.15 → 0.0.14`；静态检查与 OpenSpec 严格校验通过。
- 证据归属澄清：截图中的 `Foldout（当前属性）` 等文案来自 ASE 源码里新增的 `GetFaguiDisplayName` 硬编码表；ASEZH 仓库全历史无此代码，安装器只写 `ASELocale.` / `ASENativeDisplay.` 包装，安装回执 preimage 中也没有这些字符串。

## 结论摘要

- 问题统计：P0=0，P1=0，P2=1（设计选择，已按安全方案实施），P3=1。
- 总体判断：排除需求已用"绕开显示层"的方式落地，既达到"FAGUI 属性名不汉化"，又不牺牲其它位置的既有翻译；未发现发布阻断项。
- 发布建议：**可合并**。若用户要求把 FAGUI 面板的其它字段也一并排除，按 `AA-SCOPE-001` 追加即可。
